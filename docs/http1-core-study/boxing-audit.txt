RESULT

1. HTTP1 transport halves now reside directly inside their existing pinned worker
   futures. The workers still own each half until operation settlement and close.
   This removes two allocations per generic connection when both half types are
   non-zero-sized. It removes no per-operation allocation: those half boxes were
   already connection-lifetime allocations.
   Sites: kimojio-http1/src/io.rs:142,155 and src/driver.rs:1191-1192.

2. HTTP1 stores SleepFuture directly in State. Safe Pin::new proves the required
   Unpin bound; no unsafe projection or cancellation change is necessary.
   This removes one allocation whenever a changed Some(deadline) creates a timer.
   Native and generic HTTP1 both benefit. Runtime timer resources still allocate.
   Sites: kimojio-http1/src/driver.rs:603,1122,1315.

3. The HTTP2 interoperability server passes SleepFuture directly to select.
   This removes one allocation per fixture connection watchdog.
   Site: kimojio-http2/examples/interop_support/server.rs:80.

LAYOUT AND PERFORMANCE EVIDENCE

Concrete sizes from separately linked default and virtual-clock runtime rlibs:
                                    default   virtual-clock
  SleepFuture                           8            56 bytes
  Option<SleepFuture>                   16            56 bytes
  Option<Pin<Box<SleepFuture>>>           8             8 bytes
Thus the private HTTP1 timer field grows by 8 or 48 bytes, respectively.
The removed box formerly held another 8 or 56 bytes, plus allocator overhead.
The interop watchdog removes a fat boxed-future handle; the inline timer size
depends on the same feature configuration.

HTTP1 public client/server future size guards (<1024 bytes) still pass with both
feature configurations. The workers now include the half in the same heap
allocation as the worker future. Their outer pinned-box handles remain small.
There is no new transfer of the half on each read/write operation.
Address regression guards exercise this property through reuse and cancellation.
Construction-time moves and total worker-frame size were not benchmarked.

The allocation reductions above follow directly from the removed constructors.
They are not allocator-counter or throughput measurements. There is no CPU,
latency, peak-memory, or memcpy speedup claim. No perf profile was collected.
No frozen performance binary or hot-stack ranking applies to this audit.
The parent owns timing experiments.

RETAINED PRODUCTION BOX INVENTORY

Classification:
  A = address stability or cancellation ownership in the present design.
  E = owned public type erasure / heterogeneous values.
  L = layout or move-cost boundary, not a Rust correctness requirement.
  O = runtime-sized owned storage, not removable by substituting Vec.
  C = cold or test-fixture convenience.
No recursive type layout requires any box in the audited wrappers.

HTTP1:

  src/body.rs:72,131 [E+A]
    The non-generic OutgoingBody owns arbitrary, possibly !Unpin streams.
    Its heap source survives body/active-exchange moves. Empty/full bodies have
    no producer-stream box. from_incoming uses that existing stream path.

  src/driver.rs:158,193,270; src/transport.rs:16 [L]
    The connection/serve future retains arbitrary SplittableStream storage.
    The box prevents large inline transport buffers from inflating outer futures.
    The native client reuses this representation for a small NativeTransport.
    That native descriptor box is not required by address stability. A dedicated
    native setup representation can remove it, at a connection-time benefit.
    Decision: retain the shared representation in this bounded change rather
    than refactor the connection constructors for an unmeasured cold allocation.

  src/driver.rs:212,231,298,313 [L]
    run/run_native boxes bound nested future layouts. They are not necessary
    merely because async futures require pinning. Removing them embeds the
    complete driver state in each caller's future.

  src/driver.rs:1173 [L]
    The generic split future can contain the entire transport and large halves.
    Its box remains a boundary for arbitrary transport implementations.

  src/driver.rs:1191-1192 [A+L]
    The worker futures borrow their owned halves and operation storage across
    awaits. Existing outer boxes keep these futures pinned and keep the joined
    driver small. Only the redundant boxes around the halves were removed.

  src/io_driver.rs:146,153 [A]
    Two reusable pinned Option<F> slots per native connection. Async operation
    futures can borrow their own operation buffers/iovecs. Slot replacement
    drops completed futures in place. This is not per-read/write boxing.

  src/driver.rs:507,1138 [A+L]
    One boxed handler future per admitted server request. Active exchange
    storage moves and is replaced. Arbitrary !Unpin futures must stay pinned.
    Erasure is internal, not a public API necessity. A typed reusable slot can
    be designed, but it changes generic state/layout and requires separate
    measurements for large futures. It is not a safe textual box deletion.

LIMITS AND DECISIONS

No public type erasure was removed, no unsafe pin shortcut was added, and no
per-stream replacement allocation was introduced. Native setup descriptor boxes,
internal handler erasure, optional fixture boxes, and large-layout boundaries
remain explicit future design decisions rather than alleged safety necessities.
The two accepted commits are independent of HTTP1-core and runtime work.
